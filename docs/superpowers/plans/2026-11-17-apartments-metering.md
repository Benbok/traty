# Квартиры и показания — план реализации

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Реализовать несколько квартир, ручные показания и отметки передачи, достоверную статистику ресурсов и вопросы в существующем ИИ-ассистенте.

**Architecture:** Отдельный репозиторий квартир, Room-сущности и чистые расчёты в `data/apartments/`; экраны и их ViewModel в `ui/apartments/`. Ассистент обращается к тем же расчётам через отдельный обработчик. Новые данные сразу включаются в полную JSON-копию.

**Tech Stack:** Kotlin, Room, Compose, Flow, JUnit/Robolectric; существующие LlmClient и AppContainer. Новые библиотеки не нужны.

**Spec:** `docs/superpowers/specs/2026-11-17-apartments-metering-design.md`.

База планирования: main `2dc36e50a4f46e17304461161f51b57b66b8716d`, схема Room 16. Перед каждой веткой сверить main и существующие PR: не перезаписывать параллельную работу с чеками.

## Global Constraints

- «Загрузка PDF и фото квитанций остаётся только в плане.»
- «Денежные операции пользователь вводит только через существующую страницу транзакций». Показания не создают денежных операций.
- «Примеры вопросов и отдельный чат в разделе квартир не нужны.»
- «Все экраны используют Scaffold, TratyHeaderCard, системные отступы и существующую дизайн-систему.»
- «Сборка Android в облаке не выполняется по CLAUDE.md.»
- Никакого destructive fallback для новой схемы; JSON-схема только от реальной сборки Room.
- Файлы до ~400 строк, Composable до ~80; затрагиваемые большие блоки выносятся отдельно, механические переносы не смешиваются с поведением.
- Секреты, адреса, лицевые счета и номера приборов не нужны модели. В модель уходят только короткие названия для выбора и рассчитанные факты; отправленное доступно для просмотра.

## Review Focus

- Параллельный ввод двух показаний одной датой не обходит проверку уникальности — задача 3.
- Изменение часового пояса не создаёт второй замер за ту же выбранную дату — задачи 2–3.
- Исторический состав счётчиков с заменой не превращается в достоверный общий итог — задача 2.
- Восстановление старой копии с нулём квартир явно предупреждает об удалении текущей истории — задача 4.
- Общий финансовый вопрос о воде не перехватывается как вопрос о м³ — задача 7.
