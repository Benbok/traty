# План реализации товарных отчётов в ИИ-помощнике Traty

22 ноября 2026 · Проект для реализации · Основа ревью `f1255c8`

## Что получит пользователь

В чате можно посмотреть, какие товары встречались в покупках, какие покупались чаще, на какие ушло больше денег и что изменилось относительно предыдущего периода. Источник — сохранённые позиции покупок, включая смешанные чеки. Без ограничения по категории отчёт охватывает все товары с детализацией. Из каждой строки можно открыть подтверждающие покупки.

## 1. Описать запрос к отчёту

- В пакете `assistant/` описать типизированные параметры `product_report`. Выборка включает товар или набор товаров, категорию, магазин и период. Отдельно задаются показатель (расходы, число покупок, количество), второй период, сортировка (значение или изменение), направление изменения и лимит.
- Различать список и рейтинг. «Что я покупал?» позволяет посмотреть весь результат с раскрытием. «Пять самых частых» задаёт лимит 5. «Что покупал повторно?» дополнительно задаёт минимум две покупки.
- Поддержать прежний `product_rank` через преобразование в те же параметры. Использовать один исполнитель для старых запросов, разбора моделью и локальных правил.
- В `IntentRegistry`, `AssistantPrompts` и `AssistantQuery` согласовать описание, JSON и проверку параметров. Модель выбирает операцию одним существующим вызовом. Позиции чеков и каталог счётчиков для распознавания товарного запроса не требуются. Отдельно проверить, что вопросы про ЖКХ по-прежнему получают нужный контекст.
- Готовность: «пять продуктов», «топ-5 продуктов» и «назови пять продуктов, которые я покупаю чаще всего» в контексте рейтинга дают одинаковые параметры. Вопросы о тратах по категории общей суммой сохраняют прежнюю семантику.

## 2. Собрать единый расчёт по позициям

- Вынести товарную ветку из `AssistantEngine` в отдельный исполнитель. Использовать `ItemTotals.byProduct`, существующую нормализацию `ItemNames` и данные из репозиториев. Для первой версии достаточно расчёта на чтение поверх имеющихся записей.
- Группировать по устойчивому ключу товара. Три одинаковые позиции одного чека дают одну покупку. Расход — сумма известных стоимостей позиций в копейках. Позиции без цены участвуют в частоте и количестве, сумма маркируется как неполная. Сумму всего смешанного чека нельзя приписывать каждой позиции.
- Различать категорию транзакции и принадлежность отдельного товара. В общем отчёте брать все позиции. При фильтре по категории использовать имеющиеся сведения и проверенное сопоставление товара для смешанных чеков. Если принадлежность установить нельзя, обозначать границу выборки. Проверить на чеке, где одновременно есть молоко и бытовая химия.
- Хранить штуки, массу и объём отдельно. При ранжировании по количеству предлагать выбрать единицу, если общей единицы нет. Упаковки и их содержимое не складывать.
- Сначала агрегировать все подходящие товары, затем сортировать и применять лимит. Для равенства значений задать воспроизводимый порядок по названию и ключу. Для каждой строки сохранять идентификаторы исходных покупок.
- Готовность: на данных с частотами 4, 1, 1, 1, 1 запрос топ-5 показывает пять строк. Товар с четырьмя покупками первый, даже если разовая покупка другого товара дороже.

## 3. Добавить сравнение периодов

- Разрешать даты до расчёта в одном месте с использованием существующей логики периодов. Для частоты без срока брать всю историю. При явных датах соблюдать оба заданных интервала. Для незавершённого текущего периода по умолчанию брать столько же прошедших дней предыдущего периода, с ограничением по его последнему дню. Учитывать настройку начала финансового периода и отличать его от названного календарного месяца.
- Применять одни и те же фильтры к обоим интервалам и объединять результаты по ключу товара. Сохранять товары, встретившиеся лишь с одной стороны. Для обеих сторон возвращать границы, метрики, известность цен и число покупок с детализацией относительно подходящих покупок.
- Различать «потратил больше всего» (сортировка по сумме) и «на что расходы выросли сильнее» (по разнице). При неизвестной цене не выдавать неполную разницу за точную. Для отсутствующей строки указывать «в чеках за период не найден». При нулевой базе процент роста не вычислять.
- Готовность: на наборе из подорожавшей по сумме покупки, товара только в первом периоде и товара только во втором видны все три строки и обе даты. Для запроса «что выросло» остаются подходящие строки, есть пояснение о полноте данных.

## 4. Научить чат продолжать отчёт

- Сохранять в состоянии диалога параметры последнего выполненного отчёта и ключи показанных товаров. «А за октябрь?» меняет даты. «А только в Пятёрочке?» добавляет магазин. «А теперь по всем товарам» снимает товарное ограничение. «А какие из этих пяти покупал чаще?» пересчитывает именно названную пятёрку.
- Различать новое самостоятельное обращение и продолжение. При неоднозначности уточнять конкретный параметр. Очистка чата сбрасывает контекст. В офлайн-режиме сохранять поддерживаемые локальные запросы.
- Готовность: пройти многошаговый диалог через обычный путь отправки сообщения и проверить параметры каждого следующего расчёта, включая смену темы.

## 5. Показать отчёт и проверить результат

- Передавать из расчёта структурированные строки в карточку чата. В заголовке указывать показатель и даты. В рейтинге выводить основной показатель первым. В сравнении показывать «раньше → сейчас» и разницу. По нажатию открывать покупки выбранного товара за соответствующий период. Для длинного списка использовать раскрытие.
- Показывать полноту для каждого периода отдельно. При отсутствии детализации объяснить, по каким покупкам возможно построить отчёт. Формировать числа и строки локально.
- Автотесты: старый запрос и новый эквивалент, число словом и цифрой, разные типы товаров, смешанный чек, две строки одного товара в чеке, пропущенная цена, несовместимые единицы, ничья на границе топа, пустой период, переход года, разные длины месяцев, уточнение по показанной пятёрке. Для пути с ИИ подменить ответ модели и проверить итоговую карточку или модель её данных.
- Перед слиянием выполнить `./gradlew :app:testDebugUnitTest`, собрать APK обычным workflow и на телефоне пройти оба диалога ниже. Сверить хотя бы одну строку каждого отчёта с исходными чеками.

## Сквозная приёмка

1. «Пять продуктов, которые я покупаю чаще всего» → «А за октябрь?» → открыть чеки первого товара. Проверить число строк, даты и совпадение частоты с числом отдельных покупок.
2. «На какие товары в этом месяце я потратил больше, чем в прошлом?» → «А какие из них я стал чаще покупать?» → «А только в Пятёрочке?». Проверить сохранение выборки, смену показателя и применение магазина к обоим интервалам.

Реализацию удобно разделить на три проверяемые части: расчёт и совместимость с рейтингом (этапы 1–2), сравнение периодов (этап 3), диалог и карточка (этапы 4–5).
