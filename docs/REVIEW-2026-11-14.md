Состояние на `main` после PR #34. Оценка по пяти осям, что исправлено в этом PR и что оставлено рекомендацией (крупные переделки без возможности собрать приложение в облаке делать вслепую опасно).

## Исправлено

1. **Ключи ИИ шифруются** AES-256-GCM ключом Android Keystore (`data/secure`). Старые ключи перешифровываются при запуске. Ключ Keystore нельзя достать с телефона и он не переносится.
2. **Правила копирования данных** (`res/xml/data_extraction_rules.xml`, `backup_rules.xml`). На Android 12+ `allowBackup="false"` не отключает перенос «телефон → телефон»; теперь настройки и модель речи (~300 МБ) не переносятся. Траты по-прежнему переносятся.
3. **CSV-инъекция в экспорте.** Место, заметка, фраза, начинающиеся с `= + - @`, Excel выполнил бы как формулу. Теперь они пишутся с апострофом, импорт его снимает.
4. **Импорт не читает файл больше 20 МБ** (защита от нехватки памяти).
5. **Экспорт не роняет приложение** при ошибке записи (нет места, недоступная облачная папка).
6. **Единая точка выбора ИИ** (`AppContainer.llm`) для всех экранов, как уже было у быстрой записи.
7. **Отмена корутины не показывается как ошибка** (проверка связи, комментарий ИИ, импорт); флаг загрузки сбрасывается в `finally`.
8. **Понятные ошибки провайдера**: 401/403 — ключ, 402 — баланс, 429 — лимит; неожиданный ответ — сообщение вместо `NullPointerException`.

## Проверено, всё в порядке

- **Что уходит в ИИ.** Разбор фразы — текст фразы, список категорий, правила. Ассистент — вопрос и готовые цифры (считает приложение), названия мест. Комментарий к периоду — только суммы по категориям. Пояснение наблюдения — одно наблюдение. Сырые записи целиком не отправляются. Экран «Что ушло в ИИ» показывает отправленное.
- **Логи.** `Log.d` с текстом распознавания только при `debuggable`; в release пишутся только тексты исключений.
- **Компоненты.** Наружу открыты только лаунчер, приёмники виджетов (требование системы) и плитка (защищена `BIND_QUICK_SETTINGS_TILE`). `PendingIntent` — `FLAG_IMMUTABLE`.
- **Сеть.** Только HTTPS (DeepSeek, Yandex Cloud, Hugging Face); при targetSdk 35 cleartext запрещён по умолчанию.
- **Модель речи** скачивается с проверкой SHA-256; AAR sherpa-onnx — тоже по SHA-256.
- **Экспорт** пишется через системный выбор файла (SAF) туда, куда укажет пользователь; приложение само не кладёт копии в общие папки.
- **Поля ключей** скрыты `PasswordVisualTransformation`.

## Рекомендации (не сделано сознательно)

1. **R8/minify в release** (`isMinifyEnabled = false`). Включение уменьшит APK и затруднит разбор, но без сборки и проверки на телефоне легко сломать kotlinx-serialization, Room, Glance и JNI sherpa-onnx. Сделать отдельным PR с проверкой: собрать release, пройти запись голосом, ассистента, виджеты, экспорт/импорт.
2. **Release подписан debug-ключом.** Для раздачи знакомым лучше завести свой ключ (keystore вне git, пароли в `local.properties`). Иначе обновление поверх APK, собранного на другом компьютере, не встанет. Менять ключ у уже установленных копий нельзя без переустановки, поэтому решать это стоит до широкой раздачи.
3. **Нет схемы Room версии 10** в `app/schemas`. Миграции есть, но `MigrationTestHelper` не сможет проверить путь 9→10→11. Восстановить схему 10 можно, собрав коммит, где version = 10.
4. **Разделить `MainViewModel`** (550 строк: лента, правка, настройки, экспорт, ИИ-комментарии) на `SettingsViewModel`, `BackupViewModel` и т. д. Экраны ссылаются на неё во многих местах — без сборки рискованно.
5. **Слой репозиториев.** ~56 мест в `ui/` обращаются к `c.db.*()` напрямую. Постепенно переводить на репозитории (как уже сделано с `CategoryRepository`, `BudgetRepository`, `RecurringRepository`).
6. **Крупные файлы:** `ui/stats/StatsScreen.kt` (1250 строк), `assistant/AssistantEngine.kt` (900), `data/Database.kt` (840: все сущности, DAO и миграции). Разнести по файлам — механическая правка, удобно делать вместе со сборкой.
7. **Многомодульность и Hilt** пока не нужны: один разработчик, одно приложение. Вернуться, если появится второй вид приложения (например, Wear) или сборка станет медленной.
8. **Этап 10 плана** (PIN/биометрия, скрытие в «недавних» через `FLAG_SECURE`) — логичное продолжение защиты, когда дойдёт очередь.

## Что проверить на телефоне

- Установить поверх текущей версии: ключ ИИ должен остаться рабочим (перешифруется сам), «Проверить связь» — успешно.
- Сохранить ключ заново в настройках — работает.
- Экспорт CSV, открыть в Excel: записи с `-` или `=` в заметке показываются как текст. Импорт этого файла — без дублей.
