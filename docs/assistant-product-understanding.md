# Развитие понимания товарных запросов

1. Использовать текущий путь QuestionRules → AssistantEngine для разбора вопроса, периода и магазина. Точные совпадения считать существующим способом.
2. Для неоднозначного товара передавать настроенному провайдеру вопрос и названия из чеков. Проверять номера ответа по списку и использовать AssistantItems и AssistantSpending для одного расчёта. При нескольких трактовках сразу показывать результаты по вариантам. Сырые чеки, цены и заметки в этот запрос не включать.
3. Для больших каталогов расширить подбор кандидатов с учётом синонимов. Отдельно проверить попадание правильных названий в список до обращения к модели.
4. Добавить контекст последующих реплик («а в октябре?», «сколько литров?»). Проверять фильтры, полноту данных о фасовке и источники результата.

Регрессионные примеры должны включать разные названия одного товара, разные вкусы и марки, настоящие альтернативы, пустой период и некорректный ответ провайдера. Отдельно проверять качество выбора реального провайдера и точность локального расчёта.
