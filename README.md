# Траты — личный учёт расходов (Android)

## Состояние проекта (читать первым, если продолжаете работу)

План по этапам — [docs/PLAN.md](docs/PLAN.md). Дизайн и план этапа 2 (голос) —
[дизайн](docs/superpowers/specs/2026-11-14-voice-quick-entry-design.md),
[план](docs/superpowers/plans/2026-11-14-voice-quick-entry.md).

**Работает (проверено на телефоне Xiaomi 22041216G, Android 14):**
- этапы 0–1: учёт, категории, доходы, сверка баланса, шаблоны, правила «место → категория», импорт/экспорт CSV;
- этап 2: одна кнопка 🎤 на главной; фраза из нескольких операций, ИИ сам различает трату и пополнение;
  автосохранение уверенных трат («Сохранено N · Изменить»), общий экран подтверждения;
- распознавание речи на телефоне — GigaAM v3 (sherpa-onnx + Silero VAD), проверено 2026-11-14. Если модель не скачана
  или в Настройки → «Голос» выбран системный движок, используется системное распознавание (Google).

**Сделано в коде, на телефоне не проверялось:** панель быстрой записи (`CaptureActivity`), плитка в шторке, виджет,
очередь фраз без сети (проверить в авиарежиме).

**Осталось по этапу 2:**
- проверить на телефоне панель (в том числе повторный тап и отказ в доступе к микрофону), плитку, виджет, очередь в авиарежиме;
- критерий готовности: из 10 фраз через плитку и виджет с GigaAM ≥9 сохранены правильно (сумма, тип, категория) — не измерялся;
- не измерены скорость загрузки модели и распознавания; `FeatureConfig.featureDim = 64` (`GigaAmRuntime.kt`) не сверен
  с карточкой модели — распознавание работает, но если качество окажется низким, проверить первым;
- мелочи после ревью (ниже).

**Модель:** `gigaam_v3_e2e_ctc_int8.onnx` (320 МБ, SHA-256 `0aacb41f70f0f5aaac4b45dd430337b9e16b180f22c72af04db8516e7609c3c0`)
из https://huggingface.co/protocolvoice/asr-models, лицензия MIT. Приложение качает её само (Настройки → Голос) или её
можно положить вручную: `adb push gigaam_v3_e2e_ctc_int8.onnx /sdcard/Android/data/ru.my.traty/files/models/gigaam/`.
Словарь (`app/src/main/assets/gigaam_tokens.txt`, 257 токенов) собран из `tokenizer.model` ветки `e2e_ctc` репозитория
ai-sage/GigaAM-v3; модель детектора пауз `silero_vad.onnx` лежит там же в assets.

**Сборка:** библиотека sherpa-onnx (AAR 2.0.1, 47 МБ) скачивается Gradle-задачей `downloadSherpaAar` в `app/build`
с проверкой SHA-256 — нужен интернет при первой сборке. Нативные библиотеки только arm64-v8a (эмулятор не подходит).
Тесты: `./gradlew :app:testDebugUnitTest`. Установка на телефон: `./gradlew :app:installDebug`.

**Известные мелочи (отложено после ревью):**
- у фразы без суммы из очереди дата по умолчанию — день разбора, а не день произнесения;
- автосохранение и удаление фразы из очереди не атомарны (возможен дубль при смерти процесса);
- сумма меньше копейки проходит автосохранение, но не записывается;
- нажатие «Изменить» в момент автозакрытия панели может не успеть;
- ошибки базы внутри разбора не перехватываются;
- диалог «Запомнить правило?» может закрыть снекбар с «Изменить»;
- карточку «Разобрано, проверьте» с бессмысленной фразой нельзя удалить;
- скачивание модели не докачивается и живёт только пока жив процесс приложения;
- виджет не обновляется после ручной правки/удаления трат до следующего обновления.

Дальше по плану: этапы 3–10 (статистика, подписки, наблюдения, копилки и долги, лимиты, ассистент, защита).

---

Kotlin + Jetpack Compose + Room. Ввод голосом или текстом («кофе 250 и такси 400»),
разбор фразы через DeepSeek или YandexGPT, экран подтверждения, статистика по
категориям с сравнением с прошлым месяцем, ИИ-комментарий к месяцу, экспорт в CSV.

## 1. Что установить на Windows

1. **Android Studio** (бесплатно, developer.android.com/studio). В комплекте JDK, Android SDK,
   Gradle и эмулятор. Без него собрать Android-приложение на Windows можно, но заметно сложнее.
2. При первом запуске мастер сам скачает SDK — соглашайтесь со стандартными настройками.

VS Code можно оставить для редактирования кода, но **первую сборку сделайте в Android Studio**:
она скачает Gradle и все зависимости и создаст `local.properties` с путём к SDK.

## 2. Первая сборка

1. Распакуйте архив, например в `C:\dev\traty`.
2. Android Studio → **Open** → выберите папку `traty`. Дождитесь окончания «Gradle sync»
   (первый раз 5–15 минут: качаются зависимости).
3. Если Studio предложит обновить версии AGP/Kotlin — можно согласиться.
4. Файлов `gradlew` / `gradlew.bat` в архиве нет (их не удалось сгенерировать без сети).
   Чтобы собирать из терминала VS Code, создайте их один раз:
   в Android Studio справа панель **Gradle** → `Traty` → `Tasks` → `build setup` → **wrapper**
   (двойной клик). Появятся `gradlew.bat` и `gradle/wrapper/gradle-wrapper.jar`.

## 3. Запуск на телефоне (рекомендуется)

Микрофон и скорость работы лучше проверять на настоящем телефоне.

1. На телефоне: Настройки → О телефоне → 7 раз нажать «Номер сборки» → появятся «Для разработчиков».
2. В «Для разработчиков» включить **Отладка по USB**
   (на Xiaomi дополнительно «Установка через USB»).
3. Подключить кабелем, на телефоне разрешить отладку для этого компьютера.
4. В Android Studio выбрать телефон в списке устройств сверху → ▶ **Run**.

Без кабеля: «Отладка по Wi-Fi» (Android 11+) → в Android Studio *Pair Devices Using Wi-Fi*.

## 4. Эмулятор (по желанию)

Device Manager → Create Device → Pixel → образ с Google Play (x86_64).
Нужна включённая виртуализация в BIOS (Intel VT-x / AMD-V). Голосовой ввод в эмуляторе работает
через микрофон ПК, но удобнее тестировать на телефоне.

## 5. Работа из VS Code

После шага 2.4 в терминале VS Code (в папке проекта):

```powershell
.\gradlew.bat assembleDebug      # собрать APK → app\build\outputs\apk\debug\app-debug.apk
.\gradlew.bat installDebug       # собрать и установить на подключённый телефон
```

`adb` лежит в `%LOCALAPPDATA%\Android\Sdk\platform-tools` — добавьте эту папку в PATH,
чтобы смотреть логи: `adb logcat -s System.err AndroidRuntime`.

Для Kotlin в VS Code есть расширения, но подсказки и поиск ошибок там заметно слабее, чем в
Android Studio. Удобный вариант: писать в VS Code, сборку и отладку запускать в Android Studio.

## 6. Настройка в приложении

Вкладка **Настройки**:
- **DeepSeek**: API-ключ, модель `deepseek-chat`.
- **YandexGPT**: API-ключ сервисного аккаунта (роль `ai.languageModels.user`) и **ID каталога**
  (folder id) из консоли Yandex Cloud. Модель: `yandexgpt-lite/latest` или `yandexgpt/latest`.
- Кнопка **Проверить** отправляет тестовую фразу и показывает результат.

Ключи хранятся в приватном хранилище приложения на телефоне; в коде их нет.

├── data/Settings.kt     — ключи, выбор модели, день начала расчётного периода (DataStore)
├── data/period/BillingPeriod.kt     — границы периода (календарный месяц или «от зарплаты до зарплаты»)
├── ai/LlmClients.kt     — клиенты DeepSeek и YandexGPT
├── ai/ExpenseParsing.kt — промпт разбора, JSON → траты, офлайн-разбор без ИИ
├── ai/IncomeParsing.kt  — разбор доходов из текста и голоса
├── backup/              — экспорт и импорт CSV (CsvBackup, CsvImporter)
├── speech/             — голос: SpeechEngine, системный движок, GigaAM (GigaAmEngine, GigaAmRuntime, VadSegmenter), ModelManager
└── ui/
    ├── MainViewModel.kt, TratyRoot.kt — состояние ленты и корневой экран с навигацией
    ├── CategoriesScreen.kt — редактор категорий
    ├── home/            — лента: строки трат, диалоги подтверждения, выбор даты
    ├── stats/           — статистика по категориям
    ├── charts/          — графики «Дебет/кредит» и баланс (только просмотр)
    ├── settings/        — настройки: ключи ИИ, расчётный период

только стартовый набор для пустой базы.

Тесты: `.\gradlew.bat :app:testDebugUnitTest` (JVM + Robolectric, телефон не нужен).

## Сверка баланса и расчётный период

- **День начала периода** (Настройки, 1–28, по умолчанию 1) переключает всё приложение с «календарного месяца» на «от зарплаты до зарплаты».
- **Доходы** вводятся только переключателем «−/+» в строке ввода (текстом или голосом); экран «Графики» — только для просмотра.
- В конце периода карточка на главном экране просит **фактическую сумму по всем картам**; помогает встроенный калькулятор, названия строк запоминаются.
- Первая сверка лишь задаёт **стартовый капитал**; следующие сравнивают факт с ожидаемым: капитал с прошлой сверки + доходы − траты, **датированные позже момента той сверки**. Трата, внесённая позже, но датированная раньше, не учитывается (фактический остаток её уже отражал); импортированные из CSV строки с датой после сверки изменят следующее ожидаемое.
- **Нехватка** записывается тратой в категорию «Неучтённые» (спонтанные покупки), **излишек** — доходом «Прочее».
- Сверку можно запустить вручную: Настройки → «Сверка баланса» → «Сверить остаток»; карточку на главном экране можно отложить кнопкой «Напомнить завтра».
- Последнюю сверку можно **переделать**: кнопкой на экране результата или позже в Настройки → «Сверка баланса» → «Переделать последнюю сверку» (открывается калькулятор, новая сумма заменяет прежнюю); записи сверки нельзя править и удалять из ленты.
- Экспорт/импорт CSV теперь имеет колонку «тип» (трата/пополнение); старые файлы и файлы, пересохранённые в Excel (UTF-8 или windows-1251), по-прежнему читаются. Сами сверки в CSV не входят.
