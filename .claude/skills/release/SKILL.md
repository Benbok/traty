# Выпуск релиза «Трат»

Релиз выпускается пушем тега `vX.Y`. Дальше `.github/workflows/release.yml` на GitHub сам собирает подписанный APK и создаёт релиз. Всю механику делает `scripts/release.ps1`, этот файл описывает, как вести разговор с Arty и где нельзя действовать без его «да».

## Жёсткие правила

- **Не публиковать без явного подтверждения версии и описания.** Тег и релиз видят другие люди, тихо отозвать их нельзя. Слова вроде «ну давай потом» подтверждением не считаются.
- **Тесты обязательны.** Не использовать `-SkipTests`, пока Arty сам не сказал пропустить их в этот раз. Упали тесты, релиза нет: показать, какие тесты упали, и предложить чинить.
- **Не обходить блокировки скрипта.** Не править состояние git, чтобы проверка прошла (не делать `reset`, `push --force`, не удалять чужие теги). Если скрипт остановился, сказать Arty причину по-русски и что нужно сделать.
- **Секреты подписи** (`TRATY_KEYSTORE_*`) живут только в GitHub Secrets. Не просить их показать и не искать `.jks`-файл на диске.
- Все сообщения пользователю и описание релиза пишутся по-русски, простыми словами, без технических терминов (правило из CLAUDE.md).

## Порядок действий

1. **Подготовка.** Если в рабочей копии есть незакоммиченное или `main` расходится с `origin/main`, сначала решить это с Arty (закоммитить, `git pull`, `git push`). Релиз делается из `main`, который уже лежит на GitHub.
2. **Что изменилось.** Выполнить `powershell -NoProfile -File scripts/release.ps1 -Suggest`. Скрипт покажет последний тег и коммиты после него.
3. **Версия.** Предложить следующую и объяснить выбор:
   - только исправления: `0.1` → `0.1.1`;
   - новые функции или заметные изменения: `0.1` → `0.2`;
   - первый релиз, если тегов нет: `0.1`.
   Версию подтверждает Arty.
4. **Описание.** Написать по-русски по коммитам, для обычного пользователя:
   - раздел «Что нового» (по смыслу, а не по названиям файлов), затем «Исправлено», если есть;
   - одна строка на изменение, без номеров коммитов и технических слов;
   - в конце напоминание про установку: «Если версия не ставится поверх старой, удалите приложение (данные пропадут) и поставьте заново», только когда менялась подпись или это первый релиз с постоянным ключом.
   Сохранить текст во временный файл вне репозитория (например, `$env:TEMP\traty-notes.md`, UTF-8) и показать Arty целиком.
5. **Что нового в приложении.** До тега добавить запись в `app/src/main/java/ru/my/traty/data/whatsnew/WhatsNew.kt` (свежая сверху): `version` ровно как в теге без «v», 3–6 пунктов тем же языком, что описание релиза, у пункта `topicId` темы справки, если она есть. Если функция новая, добавить или поправить тему в `data/help/HelpTopics.kt`. Без записи с версией релиза окно «Что нового» у людей не появится. Закоммитить и запушить в `main` вместе с остальным до пробного прогона; запись показать Arty вместе с описанием.
6. **Пробный прогон.** `powershell -NoProfile -File scripts/release.ps1 -Version X.Y -NotesFile <файл> -DryRun`. Он проверяет состояние репозитория, схему БД и гоняет тесты, ничего не меняя. Тесты идут несколько минут, запускать в фоне.
7. **Подтверждение.** Спросить Arty: версия, описание, «выпускаем?». Только после явного «да» перейти дальше.
8. **Публикация.** Тот же вызов без `-DryRun`. Скрипт создаёт аннотированный тег (текст описания лежит в его сообщении) и пушит его.
9. **Слежение за сборкой.** Если репозиторий публичный, смотреть
   `https://api.github.com/repos/Benbok/traty/actions/runs?event=push&per_page=1` (поле `status`/`conclusion`); иначе попросить Arty открыть вкладку Actions. Сборка занимает 5–15 минут. Результат сообщить: ссылка на релиз `https://github.com/Benbok/traty/releases/tag/vX.Y` и имя файла `traty-X.Y.apk`.
10. **Если сборка упала.** Прочитать причину и сообщить Arty. Тег на GitHub остаётся: после исправления его нужно удалить (`git push origin --delete vX.Y` и `git tag -d vX.Y`) и выпустить заново той же версией. Удалять только с согласия Arty.

## Типичные причины падения сборки

- `Не заданы секреты…`: в Settings → Secrets and variables → Actions нет `TRATY_KEYSTORE_BASE64`, `TRATY_KEYSTORE_PASSWORD` или `TRATY_KEY_ALIAS` (или опечатка в имени).
- `Keystore was tampered with` / неверный пароль: не тот `TRATY_KEYSTORE_PASSWORD`.
- Ошибка про пароль ключа: нужен отдельный секрет `TRATY_KEY_PASSWORD`.
- Тег указывает на коммит без `release.yml`: workflow не запустится вовсе (так вышло с первыми тегами `v0.1` и `v0.0.1-test`).

## Проверка без публикации

В `release.yml` есть кнопка **Run workflow** (вкладка Actions): она собирает APK и публикует его как pre-release с указанной версией. Использовать для проверок на GitHub, когда нужно убедиться, что подпись и сборка работают.
